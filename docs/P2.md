# P2 features and verification

The Linux host/client use QUIC ALPN **`streetlight/3`**. Rebuild both ends; the new
capabilities, negotiated codec, RTT feedback and cursor messages are incompatible
with older binaries. The Mac/iPad build remains deferred and has not been accessed.

## Adaptive bitrate

Enabled by the host's `adaptive_bitrate` setting, with a checkbox in its web UI.
The requested bitrate remains the ceiling. The floor is 20% of that ceiling, at
least 1 Mbit/s and never above the ceiling. The controller evaluates cumulative
loss, FEC recovery pressure, IDR requests, actual frame progress and RTT growth in
one-second windows. Two consecutive bad windows reduce bitrate by 15%, at most
once every two seconds. Active, clean periods recover 5% every five seconds.
Idle streams do not ramp up. Startup/counter resets do not become spurious loss.

FFmpeg VA-API initializes its rate-control state at codec open; see the
[FFmpeg implementation](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavcodec/vaapi_encode.c).
Streetlight reopens only the codec context and starts a new IDR/reference chain,
retaining the VA display, frame pool, VPP, imported DMA-BUF cache, PipeWire stream
and virtual monitor. A failed reopen retains the old encoder. Host status reports
the applied bitrate. Manual SetBitrate requests are owner-only and bounded by the
same original ceiling.

```bash
cargo build --release --workspace --bins --examples
python3 scripts/p2-smoke.py
```

This script uses an isolated config and a 35-second HEVC session with packet drop
schedule `0:0,3:0.10,13:0`, followed by clean Auto/AV1 and H.264 checks. It verifies
bounded down/up adaptation, retained capture, hardware frame export, decode counts,
maximum delivery gaps and independent FFmpeg dump decoding. It sends no input and
plays no audio. `SL_TEST_DROP_SCHEDULE` is test-only; values are increasing
`seconds:probability` pairs, at most 100 stages within one hour. It defaults off,
is validated at startup and logs every transition.

## Codec negotiation

Choose **Automatic** in client settings or pass `--codec auto`. The preference is
AV1 → HEVC → H.264, limited to codecs both peers can actually use. Explicit codec
requests are checked rather than silently changed. Existing settings/default HEVC
remain valid. VA driver encode/decode profiles and FFmpeg codec availability are
queried; the Pi request-decoder path advertises HEVC only. HEVC Main10 is required
for the experimental HDR path.

The AV1 implementation selects FFmpeg's native `av1` decoder. Generic codec-ID
lookup can select software `libdav1d`, which cannot export a VA-API frame; that
failure was found and fixed during this pass. Encoded AV1 access units include a
temporal delimiter so concatenated low-overhead OBU dumps are independently decodable.
No CPU decode/copy fallback is silently advertised as hardware support.

Pi UI test: Auto selects HEVC, explicit AV1 is rejected before capture, pairing and
in-flight cancellation/restart pass. Artifacts `/tmp/streetlight-pi-ui.75udobhw`,
Pi `/tmp/streetlight-ui.nKuqJ8In`; feedback `last_frame=339`, lost=0, decode average
3.024 ms, RTT 0.537 ms.

## Cursor and relative pointer

Desktop Linux clients negotiate cursor metadata when the host's cursor setting is enabled.
The Pi defaults to embedded cursors because its tested Cage/GTK 4.18 compositor path
loses direct NV12 scan-out when a GTK overlay is visible. `SL_CLIENT_CURSOR=1` opts
into separate cursor rendering there; `=0` disables it on desktop Linux too.
Clients without that capability retain an embedded cursor. A bounds-checked
[SPA cursor parser](https://docs.pipewire.org/structspa__meta__cursor.html) handles
position/hotspot, row stride, RGBA/BGRA, hidden cursors and shape changes. Bitmap
limits are 256×256. Changed pixels travel on a reliable host→client QUIC stream;
small typed position datagrams avoid head-of-line blocking. Periodic position
refresh repairs a lost final datagram. Session epochs and serial numbers reject
old-session/reordered data. Pixels are never put into oversized QUIC datagrams.

GTK renders the cursor in an overlay with correct letterboxing, source scaling and
hotspot. Local absolute-pointer motion positions it at the local display rate;
relative mode follows the host cursor metadata. Losing focus, ending the stream
or disabling input releases pointer constraints. `--no-input` disables relative
capture as well as keyboard/mouse/gamepad forwarding.

**Ctrl+Alt+Shift+M** toggles Wayland pointer lock, using the relative-pointer and
pointer-constraints protocols on GTK's own surface. Unaccelerated motion preserves
fractional deltas. Unsupported compositors log a message and retain absolute input.
Automatic detection of a game's pointer grab on the host remains pending; the
current implementation is manually toggled. No shortcut keys were injected in tests.

```bash
SL_PROBE_POINTER_LOCK=1 scripts/e2e.sh
```

The opt-in probe mode requests a lock only on the focused/fullscreen virtual-output
probe. The test received `+10,+10,+10,+20` exactly, recorded active/released events,
and passed safe key, scroll, button, touch, gamepad, audio and UI checks. Artifacts
`/tmp/streetlight-e2e.9glUFxUI`. Normal absolute-input regression also passed at
`/tmp/streetlight-e2e.r8drlx8z`: nine cursor position updates and one valid bitmap
reached client-core, in addition to the expected input coordinates.

`SL_TEST_CURSOR=1` is a test-only host fixture: it sends a moving synthetic cursor
without injecting input or moving the real pointer. It is off by default and logs
a warning. Use `SL_TEST_CURSOR=1 python3 scripts/pi-ui-smoke.py neo.local 192.168.1.99`
to verify texture creation and retain KMS plane logs on the Pi. The script explicitly

## HDR10 status: implemented behind checks, blocked on this capture source

The experimental path requests only 10-bit RGB with BT.2020/PQ source colorimetry,
converts to P010 with explicit VA color properties, encodes HEVC Main10 and attaches
configured mastering-display/content-light metadata for FFmpeg's
[HDR SEI writer](https://raw.githubusercontent.com/FFmpeg/FFmpeg/master/libavcodec/vaapi_encode_h265.c).
The GTK presentation path uses CICP 9/16/9. It requires client capability, a suitable
hardware decoder/GTK version and validated host `hdr_metadata`; the Pi GTK 4.18
path advertises no HDR and its HDR checkbox is disabled. HDR is off by default.
No mastering values are invented for real content. Metadata values must describe
the actual source/mastering; their units and validation are in `host/src/hdr.rs`.

```bash
scripts/hdr-smoke.sh
```

This strict diagnostic uses a temporary virtual output and explicitly labeled test
mastering values. On this host it **fails** with PipeWire `no more input formats`;
no HDR frames are sent. Artifacts `/tmp/streetlight-hdr.Tvw9B1Ax`. The
[KWin screencast format table](https://raw.githubusercontent.com/KDE/kwin/master/src/plugins/screencast/screencaststream.cpp)
also lists 8-bit RGB/NV12 rather than the requested 10-bit RGB. This supports the
observed format-negotiation limitation; it does not validate HDR presentation.

A compatible compositor/capture source is required before Main10/SEI output and
physical PQ presentation can be marked verified. Stream startup refuses an
unverified format instead of relabeling SDR. The iPad EDR path is not implemented.
